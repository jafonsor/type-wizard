Decisions not in the spec:

- **Placement.** `Game.Words`, `Game.State`, `Game.Layout`, `Game.Debug` and `Game.Scene` are all in `common`. `Game.Scene` needs the renderer's types, so `common` now depends on `renderer` (which brings `jsaddle` into `common`'s plan; it already builds native and wasm, and `backend` already depends on `frontend`, which has it). That is the least invasive option: no new package, no new flake check, and the spec's own module list. `Game.State` and `Game.Words` import no renderer. Random: `splitmix` (already in the plan as a dependency of `random`).
- **Own vector type.** `Game.State.Vec2` (Doubles) so state does not import the renderer; the scene converts to `V2` (Float).
- **Shared constants** in `Game.Layout`: `playerSize` 1.2, `enemySize` 1.0, `contactDistance` = (1.2 + 1.0) / 2 = 1.1, `wordOffset` 1.0, `wordCapHeight` 0.9, `dotSpacing` 2, `dotRadius` 0.08, `defaultAspect` 16/9. The 0.9 is passed as the Text height argument as the demo did (the ticket 15 note says the em height should be about 1.25 for a 0.9 cap height; not changed here, to keep to the visual spec's literal number).
- **View aspect.** A fifth `Input`, `Aspect Double`, sets `viewAspect` (default 16:9, kept across `Start`). The render pull fires it when the Frame's aspect changes (first frame included). `Tick` keeps the spec's shape. The ring uses the aspect in force at the moment an Enemy spawns.
- **Tick fired from the pull.** The tick `Event Double` is fired by the render pull (which JS's rAF calls once per frame) through `newTriggerEvent`, not by a second JS-side hook: one callback per frame, and the value is exactly `Frame.time`. Ticks are processed asynchronously after the frame, as any trigger is.
- **Handoff cell.** `IORef (Maybe GameState)`; the Round's Settings snapshot lives inside `GameState` (`roundSettings`), so the pull calls `buildScene st.roundSettings frame st`. Before the first `Start` the cell is empty.
- **Spawn timing.** The wait before Enemy k of a Tier runs from `intervalStart` (k = 1) to `intervalEnd` (k = `enemiesPerTier`), measured from the previous spawn (from Start for the first). The first Enemy of a Round therefore appears `intervalStart` seconds in. The last Tier also ramps over its first `enemiesPerTier` Enemies and then holds. Enemies move first, then spawn, so a new Enemy is exactly on the ring in its first Tick. Several spawns can fall in one Tick (loop).
- **Ring** is `sqrt((H * aspect)^2 + H^2) / 2 + spawnRadius`, around the Player, with the world height from the Round snapshot.
- **Word shortage.** A draw fails (the spawn is deferred, the owed time stays and keeps accumulating, no duplicate, no crash) when every Word of that length is on screen or the bucket is empty. When the time comes again the spawn is retried every Tick. The shipped 400-Word placeholder has 46 to 87 Words per length, so this only shows with the tiny test lists.
- **Bags.** Created lazily per Tier on first draw. The reshuffle moves the last `min(recentCap, size - 1)` draws (`recentCap` = 10) to the back of the new bag; a one-Word bucket repeats. The lookahead can still reach a recently drawn Word (best effort, per spec).
- **`Rng`** is a newtype over splitmix's `SMGen` with an `Eq` through `unseedSMGen` (the generator has no `Eq`), so `GameState` is comparable in tests.
- **Dev hook.** `window.TypeWizardGame.state()` returns the parsed JSON written to `window.TypeWizardGame.json` (defined in `renderer.js`). It is written by `Frontend.Game` only when the page URL contains `hook` (`.../?hook`), from `Game.Debug.stateSummaryText`: phase, tier, spawned counts per Tier, enemyCount, aspect, player, and for each Enemy id, word, tier, x, y, distance. Without `?hook` nothing is built or written.
